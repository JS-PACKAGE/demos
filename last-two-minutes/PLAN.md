## 〇、專案概述

### 目標

- 在網頁中用 XYZ.js **即時渲染**整段 120 秒。時間軸控制鏡頭與事件。結束後可重播。不播放預錄影片。
- 先讓星球有重量，再讓戰火逼近；命中後用「裂開但尚未崩解」停住；最後才釋放，並且不停在爆炸最亮的一刻。
- 演出可重現：同一種子、同一時間軸，每次重播走同一條鏡頭與同一組事件。
- 倉庫齊備 `README.md`、`AGENTS.md`、`CLAUDE.md`、`PLAN.md`。

### 範圍外

- 不做遊戲：無操作戰機、無計分、無關卡、無對戰 AI。
- 不做預錄影片、離線算圖、影片檔播放或「錄成 mp4 再嵌進頁面」。
- 不修改、不 fork XYZ.js，也不把本演出放進 XYZ.js。引擎缺什麼，就在 `last-two-minutes/` 補，不回補引擎。
- 不做視覺編輯器、時間軸 GUI、Shader Graph、連線、帳號、存檔、分析。
- 不做物理驅動的艦隊對戰，也不做一般剛體碎裂模擬。崩解是編排過的碎塊與粒子，不是行星級物理破壞。
- 不要求體積雲、流體、光追，或與電影 VFX 同等的畫面。
- 不把 60fps、Safari、手機、喇叭出聲、輔助科技寫成已認證。引擎文件明示這些不在 v1.13 認證範圍。
- 不發佈 npm。不覆蓋 `xyz.js-package.xyz`。不做 demos 站首頁。
- 不改 `demos` 根目錄的 `CNAME` 與 `LICENSE`。不把本演出改成 Apache-2.0。
- 不做多語系。介面文案只用繁體中文。

## 二、系統架構

```
[觀眾瀏覽器] ──HTTPS 或 127.0.0.1──► [本演出靜態頁]
                                      ├─ src/show/contract.ts   時間、鏡頭、事件、亮度、混音的唯一真值
                                      ├─ src/show/clock.ts      模擬時鐘；暫停／隱藏不前進
                                      ├─ src/show/director.ts   依時鐘取樣，驅動鏡頭、星球狀態、事件
                                      ├─ src/scene/             星球、艦隊、武器、碎塊、粒子；只在這裡碰 xyz.js
                                      ├─ src/audio/             解鎖、八槽、增益自動化；暫停時明示停聲
                                      └─ src/ui/                開始、暫停、重播、無聲、不支援
建置：XYZ.js v1.13 3D starter（Vite）。xyz.js 以 file:vendor/xyz.js.tgz 釘選
測試：node:test 只測 contract／clock／director，不匯入 xyz.js，不需要 GPU
```

- **語言與建置**：沿用 starter 指令，不另造建置系統。開發：`pnpm dev`（先 `assets:engine`，Vite 只綁 `127.0.0.1`，不設 `GAME_BASE`，預設 `./`）。型別檢查 `pnpm typecheck`。展出建置必須 `GAME_BASE=/last-two-minutes/ pnpm build`。starter 的 `vite.config.mjs` 規定：`GAME_BASE` 只能是 `./`，或絕對路徑、以 `/` 開頭並以 `/` 結尾。`/last-two-minutes` 不合格，必須是 `/last-two-minutes/`。base 不是 `./` 時，`xyz.js` 會解析到該前綴下的 `engine/src/index.js`，發布必須帶上這棵引擎檔。starter 現況：TypeScript 6.0.3、Vite 8.3.1、pnpm@12.6.0、Node ≥ 22.13.0。在已 clone 的 `demos` 倉庫內建立目錄，指令形如：`node scripts/create-game.mjs /絕對路徑/demos/last-two-minutes --template 3d --package /絕對路徑/xyz.js-1.13.0.tgz --name last-two-minutes`。`--package` 必須指向已複核雜湊的 tarball。
- **依賴策略**：執行期只有釘選的 `xyz.js`。不加入第二個渲染器、物理庫或音訊庫。開發依賴停留在 starter 已有的 TypeScript 與 Vite，不為了測試去加瀏覽器自動化框架；視覺驗收是人工清單（Gate C）。
- **狀態儲存**：無持久化。種子與時間軸在原始碼。重播不寫檔。
- **與引擎的界線**：`src/scene/` 與 `src/audio/` 是唯一允許匯入 `xyz.js` 的地方。時間軸測試不碰渲染，避免沒有 GPU 就無法驗收契約。

## 三、演出時間軸（鏡頭與事件契約）

時間單位是模擬秒。外緣邊界是硬的。段內分點標「可調整」，但不得改段意，也不得把硬性狀態提前。

時鐘從觀眾按下「開始」或「無聲播放」之後的第一個模擬幀起算。`t = 120` 時鐘停止，畫面停在最終姿勢，直到重播。不自動循環。

| 段 | 模擬秒 | 鏡頭 | 必須看見 | 禁止 |
|---|---|---|---|---|
| 建立重量 | 0–20 | 從星球弧面緩慢拉開 | 薄大氣、地表燈光；遠方先閃一道炮火，接著艦隊掠過鏡頭 | 開場就切到爆炸或武器特寫 |
| 戰火逼近 | 20–50 | 追隨一架戰機穿過艦隊 | 炮火交錯、殘骸翻滾、護盾被擊中；**星球全程留在畫面內** | 鏡頭貼近到失去星球 |
| 地表危機 | 50–70 | 硬切到地表、朝上看 | 軌道炮火照亮天空；巨艦影子緩緩遮住光線 | 用長交叉溶解把軌道戰混成地表 |
| 無法阻止的倒數 | 70–95 | 切回軌道，並在三個主體間硬切 | 主武器光線逐漸集中；防守艦隊衝上並被擊落；至少一次安靜的星球插入 | 插入鏡頭裡新增爆炸；少於三次交替 |
| 命中後先不崩 | 95–110 | 命中，然後拉遠，停住 | 灼熱光點；裂縫沿地殼蔓延；內部光芒從裂口滲出；**輪廓仍完整**；聲音收到近乎無聲 | 地殼分離、核心強光、以暫停畫面代替靜音 |
| 崩解 | 110–120 | 維持遠景，不切回最亮特寫 | 碎塊向外翻裂、核心強光、衝擊波掃過艦隊與殘骸；亮度降下後停在塵雲、碎片，與原位置的一道光 | 以最亮幀當結尾；自動接回開場 |

### 段內分點（可調整，段意不可調）

- **95–97**：光束命中，灼點出現，混音開始下收。
- **97–104**：裂縫蔓延，內部光芒滲出，拓樸仍是完整星球。
- **104–110**：鏡頭拉遠，混音近乎無聲，留下不安的停頓。這段停頓必須有長度，不能只是一幀。
- **110–114**：碎塊外翻、核心強光、衝擊波。編排亮度的峰值落在此窗。
- **114–120**：塵雲與碎片散開，亮度低於峰值，停住。

### 張力規則（不是文案，是驗收）

先讓觀眾感到星球巨大，結尾的消失才有重量。因此開場星球必須佔滿或接近佔滿畫面，再開拉。戰火是後來才壓到眼前的東西。命中不是高潮的終點；高潮在「已經無法挽回、但還沒崩」的停頓之後才釋放。

### 鏡頭實作

- 使用根入口的 `PerspectiveCamera`，朝向呼叫其 `lookAt`。不得匯入 `camera-utils`。
- 關鍵幀存在 `src/show/contract.ts`：`t`、位置、目標、fov。段內插值；段界與倒數段的交替用硬切。
- 第二段的「星球在畫面內」要能用契約測試檢查：每個取樣的鏡頭前向與星球中心夾角小於契約內的閾值。閾值可調整，不變的是「在畫面內」。
- 觀眾版不掛互動軌道控制。除錯用的時間拖曳只允許在開發旗標下存在，正式建置不得提供自由鏡頭或任意拖時間。

### 重播

重播重置模擬時鐘、種子、粒子、聲音排程與鏡頭，回到弧面開場。按鈕必須在不重新載入頁面的情況下完成。允許另外提供「重新載入」當故障恢復，但它不是 R8 的重播。

## 四、引擎介接（XYZ.js 1.13.0，釘選發行包）

> 引擎不是遠端 API。本節定的是**本演出依賴的最小公開契約**。只經 `src/scene/`、`src/audio/` 呼叫根入口 `xyz.js`。與發行包行為衝突時，改這兩層，不改時間軸狀態機，也不改引擎位元組。

2026-10-04 已對 tag `v1.13` 查證，規範入口是該 tag 的 `docs/CURRENT.md`，不是 main，也不是舊版使用說明裡的 1.12.4 字樣。

### 4.1 發行包

- 只用 GitHub Release `v1.13` 的 `xyz.js-1.13.0.tgz`。不追 main（該 tag 發佈時 main 已有後續 commit）。
- 放入 starter 之前，本機雜湊必須同時符合 Release asset digest 與同發行的 `SHA256SUMS`。任一不一致即停止，不安裝、不改雜湊門檻。
- 建立專案用引擎自己的 `create-game.mjs --template 3d`。部署時帶上 starter 複製進 `dist` 的引擎檔，含其 vendor 音訊檔與授權，不刪、不改。
- npm 未發佈。禁止寫成 `npm install xyz.js`。

### 4.2 圖形

- 初始化可讓引擎 `auto`（WebGPU → WebGL2 → Canvas2D）。演出開始前讀取實際 backend 與 `game.graphics.capabilities`。
- WebGPU 與具備 3D 的 WebGL2：可演。WebGL2 若缺少 float color attachment，就關閉 HDR／加權透明，改用不依賴該能力的不透明或基本透明，並在畫面上不假裝效果還在。
- Canvas2D：沒有可見 3D。只顯示「此瀏覽器無法演出」，提供引擎站連結以外不再畫星球。禁止用 2D 圖形模仿本片。
- 已確認的公開型別：`PerspectiveCamera`、`InstancedMesh`、`PointLight`、`SpotLight`、`EnvironmentMap`、`FogSettings`（`linear`／`exp2`；天空與 2D 疊層不受霧影響）、`PostProcessingSettings`（`exposure`、`bloomStrength`、`bloomThreshold`、`bloomRadius`；tone mapping `none`／`aces`）。
- 不假設根入口有未查到的方向光類別。太陽用環境光加少數聚光即可。
- 陰影與燈光預算服從引擎上限，並再留餘裕：每場景點光／聚光各最多 1024、每次繪製各 32、陰影為四級串聯／八點光／八聚光。本演出設計預算更低，見五，標為可調整。
- bloom 只在能力允許時開啟。沒有 shader 轉譯器，不為裂縫另寫一套要互轉的著色器。裂縫用自發光遮罩、疊加裂縫片或實例化裂縫，不依賴 Shader Graph。
- GPU 粒子是 `GPUParticleEmitter3D`。必須在第一幀呈現前 `prepare`。Canvas2D 不支援。入場上限（不是效能認證）：capacity ≤ 65536、rate ≤ 1,000,000、lifetime ≤ 3600。本演出的設計容量遠低於此，見五。
- 貼圖若經 URL 載入：回應 ≤ 8 MiB，邊長 ≤ 8192，像素 ≤ 4,194,304。本演出預設不從 URL 載入貼圖；城市燈光用程式產生，邊長 ≤ 2048。

### 4.3 時間

- 演出時鐘吃引擎交給場景的模擬 delta。`SceneTimers` 的 `after`／`every` 可用來排一次性事件，但段界仍以 `contract.ts` 為準。
- 暫停與分頁隱藏不累積時間，這是引擎契約。本演出不得用 `setTimeout` 或 `performance.now()` 推進演出。
- 引擎的 Game pause **不會**自動暫停聲音。觀眾按下暫停時，`src/audio/` 必須另外停聲；繼續時從同一模擬時間恢復，不追趕。

### 4.4 聲音

- 官方 OPM.js v1.11.1，八個隔離槽。音樂與音效用這八槽，不另掛音訊庫。
- 解鎖需要使用者手勢，且須在安全來源。未解鎖不得開始有聲演出。
- 「聲音收掉」是增益自動化，目標在拉遠停頓時接近無聲。驗收看增益曲線，不把「有人用喇叭聽過」寫成通過。v1.13 沒有實機聽感認證。
- 曲目與音效在專案內用 OPM 音色與短 PCM 編寫。不內嵌無授權的現成音樂。

### 4.5 明確不依賴

引擎未承諾、本演出也不使用：Visual Editor、Visual Scripting、Shader Graph、Networking、原生桌面執行期、JavaScript 軟體光柵、shader 轉譯器、完整 glTF 擴充套件、three.js 相容層。崩解不呼叫 3D 物理去打碎星球；物理系統是有界基本體，不是破壞模擬器。

## 十二、小語追加的美術、電影呈現與驗收要求

本節為實作過程中追加的需求；與前文衝突時，以本節及小語最新裁示為準。`PLAN.md` 不再僅是原始企劃書的逐字副本，而是包含追加需求的執行規格。

### 12.1 先確立美術方向，再完成全片

- 先完成一艘代表性主力艦、一顆完整星球，以及一段短崩解預覽，交由小語確認。
- **先提交三個可直接觀看的即時 3D 預覽，得到確認後，才把新美術整合到完整 120 秒影片。**

### 12.2 星球必須具有真實曲面、地形與尺度

- 星球是連續的球面，不是平面拼貼；要有實際凹凸地形、山脈與海岸，不只是平滑球體上的色帶。
- 重做材質：地表顏色、海洋、陸地、山脈、日夜面、細節與城市燈光須可讀；不能是粗糙色塊或整齊金色方格。
- 使用合理的 normal、roughness、emissive 等材質細節，並在掠射光下看出地形。
- 大氣須薄且主要出現在邊緣，不能用整顆藍色透明球覆蓋地表細節。
- 星球須有清楚的體積感、明暗分界，以及一致的巨大尺度；鏡頭與艦船比例不能漂移。
- 交戰鏡頭仍遵守前文星球留在畫面的要求，完整星球在命中與裂開預覽中仍須可辨識。

### 12.3 艦船不能是積木戰爭

- 艦船須有清楚、可辨認的剪影與主體輪廓，不是幾個盒子拼起來。
- 代表艦須具有分層艦體、裝甲、凹槽、艦橋、可讀結構與引擎；細節主要透過材質和光影呈現，不以盲目增加面數取代美術。
- 重做艦船材質：金屬、裝甲板、接縫、磨損、粗糙度、反光與小尺度燈窗，不能是平塗灰色。
- 引擎噴口、尾焰、炮口與武器光效須各有外觀與節奏，不使用同一種方塊亮光。
- 新代表艦經確認後，替換全片中的積木艦船；不要只在額外頁面展示好模型，而正式演出仍保留舊造型。

### 12.4 交火、命中與爆炸必須可讀

- 雙方有互相射擊的實際演出，不只是艦船在星球旁移動。
- 炮口、射擊軌跡、命中、護盾反應與擊毀爆炸須有相互對應的時序與空間關係。
- 爆炸具有粒子與碎片，但不得用方塊粒子或過度亮光代替可辨識的命中與破壞。
- 炮火、引擎尾焰、核心漏光與塵埃有不同造型、顏色與時間節奏。
- 遠近透過速度、尺寸與亮度表達，不能讓艦船、軌道物、炮火與碎片看起來在同一個距離。

### 12.5 星球崩解是地殼撕開，不是樂高散落

- 禁止從中心噴出一堆規則立方體、整齊方片或尺寸一致的玩具碎塊。
- 碎塊須具有不規則輪廓、不同厚度、連續彎曲的外殼表面，以及可辨識的破裂內側與剖面材質。
- 碎片的大小、方向、旋轉、速度與遠近須變化；不能排列整齊或均勻放射得像展示模型。
- 可預先準備破裂幾何，不要求即時物理模擬；但預製也不能犧牲曲面與破裂外觀。
- 崩解節奏保持：**命中 → 裂縫與核心漏光 → 停住承受傷口 → 外殼翻開與核心釋放 → 震波、塵埃 → 亮度回落與殘骸。**
- 不能整段白屏或以強光遮住碎片。觀眾應不需要文字解釋，就能看懂是球形地殼被撕裂。
- 結尾必須讓人感到星球已消失、原位置只剩太空與餘光，不能停在最亮爆炸幀。

### 12.6 光影與鏡頭重做

- 重做整體光影，而不是在舊材質上加亮度。
- 太陽主光建立星球日夜明暗、山脈掠射陰影與艦體輪廓；金屬反光必須有可讀層次。
- 武器與核心光源須照亮附近物體，但不能抹掉材質或整幅畫面。
- 鏡頭有清楚主體與前景、中景、背景；代表艦掠過、命中全貌、崩解殘骸各有明確構圖。
- 在鏡頭與距離安排下，星球始終具有巨大重量，不以快速亂移鏡頭掩飾尺度問題。

### 12.7 電影頁面不得出現捲軸

- 正式演出與代表性預覽均須完整容納於目前視窗，不得出現垂直或水平頁面捲軸。
- 舞台是視窗內的電影畫面，不是需要捲動的展示網頁。
- 控制列、預覽切換、時間與必要狀態採覆蓋式呈現，不把影片往下擠。
- 除啟動、暫停或控制操作外，觀看中應減少介面干擾；控制仍須能以滑鼠、觸控與鍵盤使用。
- 窄螢幕、直向螢幕與低高度視窗亦須保持控制可用，不以裁掉畫面或隱藏必要按鈕冒充無捲軸。

### 12.8 引擎實作與效能證據

- 所有預覽與正式影片皆是 XYZ.js 1.13.0 的實際即時渲染，不以圖片、預錄影片、假 API 或 mock 取代。
- 使用功能前先核對釘選版本的公開 API、型別與官方範例；若缺少所需能力，明確寫出限制，不假裝引擎支援。
- 選定並記錄實際裝置、瀏覽器、解析度與 WebGPU／WebGL2 後端，再量測幀時間與尖峰；不能只說「應該流暢」。
- 分清實際幀間隔、CPU submission 與 GPU timestamp；不支援 GPU 計時時寫明未量得，不將 CPU 時間當 GPU 時間。
- 優化碎片數量、粒子容量、遠景細節、貼圖與資源預載；不能把好看的地殼與艦體退化成方塊來換效能。
- 全片重播最終仍須在同頁完成，重設鏡頭、碎片、粒子、音訊、時間與 seed；暫停或隱藏頁面不累積演出時間。

### 12.9 三個代表性預覽的交付 Gate

1. **艦船掠過星球**：可直接開啟，能看到艦船輪廓、裝甲材質、金屬光影、引擎與星球的巨大尺度。
2. **命中與裂口**：可直接開啟，完整球面仍可辨識，地形與地表仍可讀，裂縫逐步出現並露出核心光，不提早散開。
3. **地殼崩解後**：可直接開啟，展示不規則厚曲面碎片、破裂內側、翻轉、震波與分層塵埃，最後亮度回落。
4. 三段都無頁面捲軸；附實際裝置、解析度、後端、幀時間與尖峰量測。
5. 清楚標示預覽不是完成全片。不使用占位模型、強光遮掩、靜態圖片或假渲染達成驗收。
6. **待小語確認代表性視覺方向後，才繼續完整影片整合。** 完成全片後仍須逐項驗證前文 Gate C 的完整 120 秒、暫停、同頁重播、結尾與拒絕路徑。

### 12.10 開發環境開放連線的追加裁示

- 小語先要求 listen `0.0.0.0`，隨後更正為 **listen `127.0.0.1`**；以最新更正為準。
- 開發伺服器只綁 loopback，但接受任何網址的 Host：Vite `server.host: '127.0.0.1'`、`server.allowedHosts: true`。允許所有 Host 的要求未撤回。
- `pnpm dev` 由 Vite 設定控制監聽位址，不以 CLI host 覆蓋。重新啟動後，實際確認僅監聽 loopback，以及任意 Host header 的 HTTP 請求成功。
- 允許所有 Host 會取消 hostname／DNS-rebinding 防護；僅在可信環境使用，不改正式建置的 CSP，不修改 Pages 正式部署安全性。
- 接受 Host 不代表網域自動解析到本機，也不繞過 WebGPU／音訊的瀏覽器安全來源限制。正式或非 loopback 網域仍應透過 HTTPS 使用。

### 12.11 配樂必須發揮官方 OPM.js 的能力

- 小語指出原配樂不好聽，也沒有發揮強大的 OPM.js 引擎；必須重做，而不是沿用單音低頻與零散提示音。
- 使用官方 OPM 的原創 FM 音色，編寫可辨識的主題、分聲部和聲、低音推進與戰鬥節奏；不能換另一套合成器或拿既有電影配樂冒充原創。
- 開場、交戰、地表、倒數、命中後留白與崩解收束須有各自的編曲與動態，不把同一小段 drone 循環兩分鐘。
- 命中後保留近乎無聲的張力；結尾降亮時聲音也須收束，不以更多爆音或更大音量掩蓋編曲問題。
- 音色、音符與效果須經釘選版本的真實公開 API 播放；型別檢查、八個 context 建立成功，均不能代替實際 DSP 輸出證據。
- 維持官方八槽上限，計入 release tail；以實際播放驗證手勢解鎖、暫停、恢復、同頁重播與停止，不假裝畫面暫停就等於音訊暫停。
- 在代表性預覽提供可由使用者手勢開啟的配樂試聽；音樂聽感與視覺方向仍由小語確認，未確認前不宣稱完成全片。

### 12.12 型別、資料結構與實際展示

- 不以 `ReturnType<typeof 具體函數>` 間接推導公開或持久狀態的型別契約；使用清楚的具名型別或直接型別。
- 固定字串鍵的靜態對照表使用 `Record`；需要動態新增、清除或數值鍵的執行期集合仍可使用 `Map`，不為形式統一而改壞資料結構。
- 小語要求開啟瀏覽器展示當前成果；須真的打開可觀看頁面，不只提供程式碼、建置 log 或口頭描述。
- 展示新美術時直接開三段新預覽，清楚區分舊時間軸原型與新成果；不得把舊畫面當作新版本交付。

### 12.13 XYZ 即時畫面的細節深化

- 小語指出 XYZ 引擎可以呈現更細緻的畫面；目前作品的粗糙程度不能當作引擎能力上限。
- 在三段待審預覽深化多尺度海岸、山脈、海水與陸地材質，加入可辨識的獨立曲面雲層；保留地表與日夜分界，不以整顆不透明雲球遮蓋。
- 主力艦須有分段倒角裝甲、外露機械通道、管線、散熱結構、中空炮口與分層噴嘴，不靠隨機裝飾或強光冒充精細。
- 厚曲面碎塊須有多層凹凸剖面與岩層材質；裂縫應有暗色破裂邊緣與細熱光，明確區分表面裂口造型與真正切開球體。
- 以實際影片構圖確認細節可讀，再量測成本；增加貼圖解析度或三角形數本身不構成驗收。仍須先確認預覽方向，不擅自整合全片。

### 12.14 第二輪預覽質感深化

- 再深化連續海岸、方向性山脈與山谷、植被／乾燥／冰雪過渡及局部聚落，避免全球規則格線與剪紙式地貌。
- 曲面雲層以 PBR BLEND 保留連續 alpha；下方地表必須 OPAQUE 並先寫入深度，不以不透明整球遮蓋。雲仍是貼圖薄殼，不是體積雲。
- 艦體加入凹入維修艙、雙層裝甲、機械底床、材質分區與分層噴嘴；破裂採不等尺寸、缺口輪廓的厚曲面岩層與少數較慢的大塊。
- 震波帶有不規則波紋，隨時間降低透明度；修正實測發現的 WGSL uniform 引用錯誤。三段最新 WebGPU 預覽及成本見 README；不宣稱全片或 60fps 通過。

### 12.15 飛船引擎必須有持續粒子流

- 小語要求「飛船加上尾焰的粒子流，才像是有引擎在推動」；不是只放靜態發光錐體。
- 三個分層噴嘴各自掛一個原生 GPU 發射器，中間暖色、兩側藍色；持續向艦尾噴射，加入小幅速度分散，粒子縮小並淡出。
- 噴嘴跟隨艦體，已發射粒子保留 world-space 軌跡；太空尾流不受重力下墜。
- 每個發射器 capacity 256、rate 180/s、lifetime 0.8s；僅在掠過預覽建立並啟動，不把預覽預算混入尚待整合的全片。
- 預載全部完成、鏡頭與艦船歸位後才啟動；暫停停止模擬，12 秒結束停止發射與模擬，同頁重播銷毀舊發射器並以相同種子重新建立。
- WebGPU 實際檢查尾流畫面、暫停 1.5 秒、結尾停住及同頁重播；驗證結果與效能限制記錄在 README。視覺方向仍待小語確認。

### 12.16 星球板塊高低落差與寫實方向

- 小語要求「星球板塊要明顯，高低起來要有」，隨後追加「星球盡可能逼真」；採自然大陸架、高原、谷地與交界山脈，不做浮起的拼圖或規則描邊。
- 地形由 20 個 seeded 球面板塊形成寬緩高度差，扭曲邊界與壓縮隆起接上原有山脈、侵蝕細節；陸地由海岸逐漸升高，海面保持等高。
- 地表網格改為 256×128 分段，實際 33,153 頂點、65,024 三角形；半徑 10、高度上限 0.45。高度刻意適量強化以利遠景辨識，不宣稱精確地球比例、地質模擬或已達照片級擬真。
- 地形法線由實際三角面加權並接合經線，normal map 只補細部侵蝕，不重複放大整座山；岩石與積雪依隆起及高度過渡，聚落避開主要隆起。
- 雲殼與視角薄大氣沿地形保持小間距，不以最高山峰為整球膨脹半徑；大氣不自發光，最外緣淡出、受日照調制。雲與大氣仍是薄殼近似，不是體積散射。
- 已實際檢查三段 WebGPU 預覽、地形接縫與法線；前綴建置、型別檢查及既有 10 個測試通過。最新成本見 README；維持美術審閱 Gate，不整合全片或對外發布。

### 12.17 進一步提高星球寫實感

- 小語再次要求「星球可以更逼真」；維持虛構星球與板塊高低差，不換成地球照片，也不增加遠端貼圖依賴。
- 降低大片高原基底，細化海岸、緯度與降雨生態區、山地岩色與雪線；海水與陸地分別呈現低／高 roughness。
- 用 2048×1024 光學厚度雲圖呈現局部旋轉天氣、破碎雲帶與細雲，保留足夠透明空隙；使用 PBR 日照，而非整片白色雲球。
- 修正實測發現的地表預設 BLEND 排序問題，明確改 OPAQUE；大氣 native hook 正確輸出 premultiplied RGB，依視角增厚並淡出外緣，避免硬線。
- 已檢查三段 WebGPU 畫面、同頁重播與球面接縫／法線；前綴建置、型別檢查及 10 個既有測試通過。最新量測與薄殼／無雲影限制見 README；仍待美術審閱，不整合全片或發布。

### 12.18 命中區必須像巨大岩層撕裂，不像碎蛋殼

- 小語指出不能只用紅線，也不能把尺寸接近的硬殼整齊抬起；優先改善碎片形狀、斷面與內部層次，不增加爆光或粒子掩蓋。
- 命中預覽改為真正分割原球面網格；破壞區多尺度、不等大小，裂邊按連續扭曲場切入三角面，不沿經緯網格形成規律階梯。保留球殼曲率、表面地貌與可辨識的星球輪廓。
- 斷面有粗糙翹邊、尖角、三層變厚斜裂、局部幾何岩屑；中心塌陷、周邊局部錯位，不以全殼等幅散開代替岩層破壞。
- 裂口下方不再繪製完整地表；中心採焦岩，深處為暗色熔融層。雲層實際退開，內側點光照亮斷面，避免沿上緣畫熱紅線冒充內部層次。
- 實際 WebGPU 三段畫面與 factory smoke 已確認有限幾何、法線、雲遮罩、位移、崩解及 reset；建置、型別檢查與 10 個既有測試通過。成本與非物理模擬限制見 README；仍只修改開發美術預覽，未整合完整影片或通過美術審閱。

### 12.19 戰艦必須互相交火，受創燃燒與爆炸要有真實感

- 小語要求可讀的互相射擊，不是任意閃光；另要求燃燒與爆炸具有真實感。先完成獨立交火預覽，不擅自整合或發布完整影片。
- 四艘對向艦船以解析姿態移動；砲塔與砲管瞄準解算後的移動裝甲接觸點。有限速度砲彈從實際砲口出發，命中前不提前顯示傷害，致命命中後受害艦不再射擊。
- 編排包含護盾攔截、裝甲破口、持續燃料噴流、短暫爆燃與厚裝甲碎片冷卻漂移。噴流沿破口法線向外，整個體積保持在裝甲外；局部燈光隨燃料耗盡消退，不以大面積 bloom、無重力環境中的向上煙柱或不降亮火球掩蓋艦體。
- 戰鬥音效按實際發射／命中時刻播放；已觀測原生音訊來源與暫停、結尾及重播時鐘對應，未驗證喇叭聽感。四段預覽在橫直向介面皆可操作。
- 建置、型別檢查與 17 個測試通過；WebGPU 已實際播放交火、燃燒、擊毀與冷卻。factory smoke 的 95 個燃燒 mesh 取樣未穿入裝甲，12 秒時命中燈光全數歸零。燃燒是解析幾何／shader 演出，非物理模擬；WebGL2、實體手機與完整新美術影片仍未驗證。

### 12.20 交火不能像回合制，瞄準必須花時間

- 小語要求射擊具有隨機性，不能固定兩邊輪流開火；砲塔不可瞬間瞄準就射擊。
- 移除固定交替 volleys。每艘兩座前向砲塔使用獨立 seeded random 的索敵延遲、裝填間隔、目標與砲管選擇；雙方可以同時射擊，同 seed 保留可重現的重播。最終擊毀與冷卻仍是 12 秒預覽的導演節點，不改成無終點的戰鬥模擬。
- 瞄準從上一次角度連續轉向／俯仰，依角度差與速度限制決定所需時間，之後還要穩定瞄準才能開火；發射角度與真實砲口、移動裝甲的預測接觸點一致。未改為每幀抽亂數或以瞬間旋轉掩蓋瞄準時間。
